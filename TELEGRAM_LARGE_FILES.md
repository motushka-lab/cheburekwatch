# Большие видео через Telegram

Сайт и официальный `telegram-bot-api --local` запускаются в одном Docker-контейнере. Telegram API слушает только `127.0.0.1:8081`; браузер получает видео через авторизованный маршрут CheburekWatch. Видео не загружается целиком в память Node.js. База остаётся в `/var/data/db.json`, Telegram-сессия и файлы — в `/var/data/telegram` на том же persistent disk.

Local Bot API снимает ограничение **скачивания ботом** в 20 МБ. Ограничение отправки файлов самим пользователем в Telegram остаётся ограничением его аккаунта/клиента. Указанные Telegram 2000 МБ относятся к **исходящей загрузке через Bot API**, а не к лимиту скачивания нашим сервером.

Официальные источники: [Telegram Bot API Server](https://github.com/tdlib/telegram-bot-api#usage), [получение API ID](https://core.telegram.org/api/obtaining_api_id), [Render Docker](https://render.com/docs/docker), [Render persistent disk](https://render.com/docs/disks).

## Обновление существующего Render-сервиса

1. На [my.telegram.org](https://my.telegram.org) открой **API development tools**, создай приложение и получи `api_id` и `api_hash`. Это отдельные параметры Telegram, не токен BotFather. Вводи их непосредственно в Render, не в чат и не в GitHub.
2. В **существующем** сервисе CheburekWatch → **Environment** сохрани текущие `TELEGRAM_BOT_TOKEN` и `TELEGRAM_ADMIN_ID`, добавь:

   | Переменная | Значение |
   | --- | --- |
   | `TELEGRAM_API_ID` | твой `api_id` |
   | `TELEGRAM_API_HASH` | твой `api_hash` |
   | `TELEGRAM_LOCAL_API` | `true` |
   | `TELEGRAM_LOCAL_DIR` | `/var/data/telegram` |
   | `TELEGRAM_MIGRATE_FROM_CLOUD` | `true` |
   | `DATA_DIR` | `/var/data` |

   В контейнере `TELEGRAM_BOT_API_BASE=http://127.0.0.1:8081` устанавливается автоматически.
3. Проверь диск **cheburekwatch-data**, mount path **/var/data**. Рекомендуемый начальный размер — **20 ГБ**, память сервиса — **2 ГБ** (`1c-2g`). Эти изменения увеличивают оплату Render; проверяй стоимость в его панели перед применением. Диск можно увеличивать, но нельзя уменьшать. Не удаляй существующий диск: на нём пользователи, комнаты и библиотека.
4. Примени изменения кода из GitHub. Если сервис управляется Blueprint, синхронизируй обновлённый `render.yaml`. Для ручного сервиса смени runtime на **Docker** в Settings по [инструкции Render](https://render.com/docs/native-runtimes), Dockerfile path — `./Dockerfile`. Убери старую Docker Command override, если она задана: запуск должен использовать `CMD` из Dockerfile, а не `npm start`.
5. Дождись сборки и deploy. Первая сборка компилирует официальный сервер Telegram и может занять заметно больше времени, чем `npm ci`.
6. В логах ожидаются `Telegram bot migrated from the cloud API.`, `Local Telegram Bot API ready; starting CheburekWatch.` и `Telegram library bot ready`. Первый переход выполняет облачный `logOut` автоматически, затем сохраняет отметку на persistent disk. При перезапусках облачный `logOut` не повторяется. После успешного перехода можно выставить `TELEGRAM_MIGRATE_FROM_CLOUD=false`.
7. Отправь боту `/start`, затем видео **как документ** с подписью `Название | 1`. MP4 с H.264/AAC — удобный вариант для браузерного плеера. MKV и другие неподдерживаемые форматы эта работа не конвертирует.
8. Бот ответит `Получено … Скачиваю на сервер`, затем `Сохранено … Теперь она доступна на сайте`. До второго сообщения запись не публикуется. Выбери её в комнате через **СМЕНИТЬ КИНО → БИБЛИОТЕКА**, проверь воспроизведение, перемотку и синхронизацию во втором браузере. После перезапуска сервиса повтори проверку.

## Поведение и ограничения

- На подготовку большого файла выделяется до 30 минут. Готовый путь хранится в закрытой серверной базе и используется при перемотке без повторного `getFile`. Если файл исчез, сервер пытается заново разрешить его через Telegram.
- Загрузка последовательная. Пока скачивается серия, следующие команды бота ждут; сайт и уже скачанные видео работают. Если сервис перезапустится до подтверждения, проверь `/list` и при необходимости отправь файл ещё раз.
- Перед новым скачиванием проверяется свободное место с резервом 256 МБ. При нехватке места серия не публикуется.
- `/delete` удаляет запись из библиотеки, **не очищает внутренний файловый кеш TDLib**. Учитывай накопление кеша при выборе диска. Не удаляй весь `/var/data` для освобождения места. Автоматическая очистка кеша и перекодирование видео в этот этап не входят.
- Не запускай одновременно второй экземпляр того же бота через облачный API или на другом сервере. Сохраняй один экземпляр сервиса и общий persistent disk.
- Если локальный процесс или сайт падает, контейнер завершает второй процесс, чтобы Render перезапустил оба. При отсутствии API ID/hash локальный режим завершается с понятной ошибкой; скрытого возврата к лимиту 20 МБ нет.
- Для возврата к облачному API одного изменения URL недостаточно: нужен корректный выход из локального API, а после облачного `logOut` Telegram блокирует повторный облачный вход на 10 минут. Не переключай API наугад.

## Проверки разработчика

```bash
npm ci
npm test
docker build -t cheburekwatch .
docker run --rm --entrypoint telegram-bot-api cheburekwatch --version
```

GitHub Actions проверяет Node.js, интеграционные тесты, сборку Docker и запуск `/health`. Интеграционные тесты используют имитацию Telegram API и разреженный файл 350 МБ: реальных Telegram-ключей в тестах нет. Реальная доставка Telegram и возможности конкретного Render-инстанса проверяются после добавления секретов и deploy.
