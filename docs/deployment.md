# Развёртывание на Render

[Вернуться к README](../README.md)

Текущая конфигурация находится в [render.yaml](../render.yaml). Она запускает Node.js/Express-сервис и сохраняет базу на постоянном диске.

| Параметр | Значение в конфигурации |
| --- | --- |
| Runtime | Node.js |
| Build command | `npm ci` |
| Start command | `npm start` |
| Health check | `/health` |
| Переменная `NODE_ENV` | `production` |
| Переменная `DATA_DIR` | `/var/data` |
| Диск | `cheburekwatch-data`, 1 ГБ, путь `/var/data` |

## Существующий сервис

Обновляй код в подключённой ветке `main`. Конфигурация включает автоматический деплой при коммите. Сохраняй существующий диск и `DATA_DIR`: в `/var/data/db.json` находятся пользователи, сессии, комнаты, сообщения и библиотека.

Если сервис управляется Blueprint, изменения `render.yaml` применяются через синхронизацию этого Blueprint. Секреты задаются в Render Environment.

## Новый сервис

Подключи репозиторий `motushka-lab/cheburekwatch` к Render Blueprint и используй `render.yaml` из корня. Конфигурация содержит платный сервис с постоянным диском; проверь стоимость перед созданием.

## Telegram-библиотека

Задай в Environment:

- `TELEGRAM_BOT_TOKEN` — токен бота от BotFather;
- `TELEGRAM_ADMIN_ID` — числовой Telegram ID администратора.

Бот является частью `server.js`. Справка по формату добавления видео доступна через `/help`. Добавленные серии открываются в комнате через «СМЕНИТЬ КИНО → БИБЛИОТЕКА».

В этой конфигурации используется обычный Telegram Bot API. Переход на Local Bot API и большие файлы подготовлен отдельно в [PR №1](https://github.com/motushka-lab/cheburekwatch/pull/1); он требует своей настройки и не включается уборкой репозитория.

## Проверка после деплоя

Открой `https://<адрес-сервиса>/health`: ожидается `{"ok":true}`. Затем проверь вход, создание комнаты, видео, синхронизацию во второй вкладке и чат.

Frontend и `/api` обслуживаются одним сервисом. Пользовательские данные и настоящие токены в GitHub не добавляются.
